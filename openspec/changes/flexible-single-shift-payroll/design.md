# Design: Flexible Single-Shift Payroll

## Approach

Deepen `AttendanceShiftAnalyzer`/`PayrollShiftEvaluator`; preserve marks, `Fecha laboral`, exact minutes, append-only decisions, immutable history, and legacy/current reports. Immutable publication `payroll_policy_key` is the sole gate: all legacy profiles use `schedule-overlap-v1`; only explicitly published new 06:00–14:00 Monday–Saturday/Sunday-off general policy uses `duration-first-v2`. Schedule shape, `profile_key`, profile version, `definition_hash`, and global `rules_version` never gate behavior. V2 implements the four authoritative delta specs.

## Transaction and Resolution Contract

`PayrollContextTargets(payPeriodIds,profileIds,publicationIds,employeeIds,assignmentIds,rawMarkIds,holidayStart,holidayEnd)` and `LockedPayrollContext(company,payPeriods,profiles,publications,employees,assignments,rawMarks,holidayCalendar)` expose sorted keyed strict accessors. Sole payroll transaction owner `PayrollContextLocker::within` locks `company→periods→profiles→publications→employees→assignments→rawMarks`, each `ORDER BY id`; workers never transact/lock.

`HolidayCalendar::captureLocked(LockedPayrollContext $context,CarbonInterface|string $start,CarbonInterface|string|null $end=null)` reads lock-free after `within` builds an uncalendared context; standalone capture uses `captureHolidayCalendar(companyId,start,end)`. Processor/review become public locker wrappers plus locked workers; evaluation requires supplied calendar. `PayPeriodCreator`, publisher, retirer, `Nomina/Revisar`, calendar tests, and PostgreSQL worker use those wrappers; remove surrounding transactions. PR5 migrates `EmployeeScheduleAssigner` transaction ownership and focused proof to company→profile lock order; no nested profile→company path survives. PR7 uses the migrated assigner for publication/activation/UI/reassignment. `PayrollContextLockOrderTest` asserts level 1, no savepoint/second company lock, exact order, and public-path races.

`ProcessPayrollRun::begin` commits its short job-state transaction before calling `PayrollProcessor` outside any job transaction; the processor owns payroll atomicity, then `complete` uses a separate short job-state transaction. Failure recording is likewise separate. No job transaction encloses payroll, no savepoint/second company lock; retry/state-transition tests prove queued→processing→completed/failed handoff.

Exact-one `Fecha laboral` resolution counts assignment→same-company profile→profile publication `[from,to)`→weekday schedule in live and `PayrollPeriodSnapshotData` paths; zero/multiple blocks review/processing. Readonly `ShiftOccurrence(publicationId,payrollPolicyKey)` feeds analyzer dispatch. Publication identity joins assignment/schedule/calendar/mark revisions in candidate, deficit, variation, and retry fingerprints.

## Executable Schema Contracts

Existing rows default/backfill `record_version=1`; new writers set `2`.

- `attendance_exceptions`: `record_version smallint NOT NULL DEFAULT 1`; nullable `starts_at,ends_at`; existing key/fingerprint/kind/minutes/rates/decision/reason/created-at remain NOT NULL, actor/parent nullable. V1 remains byte-compatible. V2 requires `daily_shortfall`, NULL interval, `minutes 1..480`, decision `granted|rejected|revoked`, hex keys, actor/reason, ordinary rate exactly `minutes`, other four rates zero; grant/reject have no parent, revoke supersedes the equal current v2 grant. Trigger violations: `23514`.
- `attendance_variation_acknowledgements`: `id bigserial PRIMARY KEY`; `record_version smallint NOT NULL DEFAULT 2`; non-null bigint FKs `company_id,pay_period_id,employee_id,acknowledged_by` (`RESTRICT` actor); non-null `work_date date,variation_key char(64),fingerprint char(64),variation_kind varchar(32),entry_at timestamp(0),reason text,created_at timestamp(0) DEFAULT CURRENT_TIMESTAMP`; CHECK v2/`schedule_entry`/hex/nonblank; UNIQUE `(company_id,pay_period_id,employee_id,work_date,variation_key,fingerprint)`; append-only, no update/supersession columns.
- `overtime_decisions`: add `record_version smallint NOT NULL DEFAULT 1` and nullable `resolution_kind varchar(20),approved_starts_at/approved_ends_at/rejected_before_starts_at/rejected_before_ends_at/rejected_after_starts_at/rejected_after_ends_at timestamp(0),approved_minutes/rejected_minutes/rejected_before_minutes/rejected_after_minutes integer,approved_rate_minutes/rejected_rate_minutes json,resolution_hash char(64)`; existing candidate/fingerprint/kind/start/end/minutes/rates/decision/reason/created-at remain NOT NULL, actor/parent/batch nullable. V1 requires additions NULL. V2 requires `post_quota_overtime`, actor/reason/hex, positive whole-minute candidate, `whole_approve|whole_reject|partial`; partial is nonempty contiguous, batch-forbidden, and before+approved+after exactly partitions the candidate. Candidate/approved/rejected JSON contain only nonnegative `{ordinary,extra25,extra50,extra75,extra100}`; totals and each band conserve exactly. Supersession preserves candidate fields or fails `23514`.

Publication migration first adds parent `UNIQUE(company_id,profile_key,id)`, then creates `id bigserial PRIMARY KEY`; non-null `company_id bigint REFERENCES companies(id),profile_key varchar,profile_id bigint,payroll_policy_key varchar(32),effective_from date,definition_hash/request_key/payload_hash char(64),reason text,created_at/updated_at timestamp(0)`; nullable `effective_to date,published_by bigint REFERENCES users(id) ON DELETE RESTRICT` (NULL legacy only). Add child UNIQUE `(company_id,profile_key,id)`, UNIQUE `(company_id,profile_key,request_key)`, composite profile FK; CHECK dates/nonblank/hex, key IN `schedule-overlap-v1|duration-first-v2`, and `duration-first-v2⇒profile_key='general' AND published_by IS NOT NULL`.

Enable `btree_gist`; `EXCLUDE USING gist` overlapping `(company_id,profile_id,daterange(effective_from,COALESCE(effective_to,'infinity'::date),'[)'))` for all rows and `(company_id,profile_key,daterange(effective_from,COALESCE(effective_to,'infinity'::date),'[)')) WHERE duration-first-v2`. Immutable trigger permits only one locked `effective_to NULL→date`; other UPDATE/DELETE fails `23514`. Backfill maps inclusive assignment ranges to `[effective_from,effective_to + 1 day)`; NULL stays unbounded. Group by `(company_id,profile_id)`, sort deterministically, then coalesce overlapping/adjacent ranges into a canonical union before insertion. Create one `schedule-overlap-v1` publication per union range regardless key, preserving every final work date and total valid legacy coverage without shared-profile overlap. Validate all rows first; dangling/cross-company/invalid/overlapping employee assignments fail closed before writes. Focused PostgreSQL REDs prove final-date preservation and shared-profile coalescing/non-overlap. Normal profile creation writes legacy identity; only publisher writes v2. PostgreSQL tests enforce `23514`, FK `23503`, request `23505`, overlap `23P01`; only identical `23505/23P01` fresh-lock reload succeeds, else `publication_conflict`.
